# Programación

Apuntes del módulo de **Programación de 1.º de DAM**, organizados para estudiar los conceptos de forma progresiva y con el menor ruido posible.

:::tip[Cómo usar estos apuntes]
No intentes memorizar código. La idea es entender cada concepto, probar los ejemplos y después resolver ejercicios sin mirar la solución.
:::

## Antes de empezar

Consulta primero la [Guía del módulo](./00-guia-del-modulo/) para conocer:

- Cómo se evalúa la asignatura.
- Qué evaluaciones son obligatorias.
- El peso de cada examen.
- El sistema de redondeo.
- El formato de las pruebas.

## Temario

### 1. Fundamentos

Conceptos básicos necesarios para empezar a programar en Java.

- Variables y tipos de datos.
- Operadores.
- Entrada y salida de datos.
- Expresiones.

### 2. Control de flujo

Cómo conseguir que un programa tome decisiones y repita acciones.

- Condicionales.
- Bucles.

### 3. Estructuras de datos

Cómo trabajar con conjuntos de valores.

- Arrays.
- Matrices.
- Otras estructuras que aparezcan durante el curso.

### 4. Programación estructurada

Cómo dividir un programa en partes más pequeñas y reutilizables.

- Métodos.
- Parámetros.
- Valores de retorno.
- Ámbito de variables.

### 5. Programación orientada a objetos

Conceptos fundamentales de POO en Java.

- Clases y objetos.
- Atributos.
- Métodos.
- Constructores.
- Encapsulación.
- Herencia y polimorfismo.

> El índice se irá ajustando al temario real de la asignatura a medida que avance el curso.

---

## Método de estudio recomendado

Para cada tema:

1. Lee la explicación inicial.
2. Ejecuta los ejemplos por tu cuenta.
3. Intenta explicar el concepto sin consultar los apuntes.
4. Resuelve los ejercicios.
5. Revisa los errores frecuentes.
6. Haz una segunda pasada sin ayuda del IDE cuando se acerque un examen en papel.

:::caution[Primera evaluación]
La primera prueba se realizará **en papel**, por lo que conviene practicar también la escritura y lectura de código sin depender de NetBeans.
:::

## Objetivo

Al terminar el módulo deberías poder leer un problema, descomponerlo en pasos y escribir un programa que lo resuelva, entendiendo por qué funciona cada parte del código.
